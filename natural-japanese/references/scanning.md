# 原稿の検査

スクリプトは登録済みの表現を拾う。文脈による適否は判断せず、自動置換もしない。
候補が出たら前後の文を読み、`word-choice.json` の `keep_when` も確認する。
残す表現について説明が求められた場合は、その文で適切な理由を伝える。

## 使い方

スキルのディレクトリを基準にした例。別の場所で実行する場合はスクリプトの
パスを指定する。ファイルは変更されない。

```bash
python3 scripts/check_japanese.py draft.md
python3 scripts/check_japanese.py draft.md reply.md --format json
python3 scripts/check_japanese.py < draft.md
python3 scripts/check_japanese.py --input-format text < message.txt
```

入力を省略するか `-` を指定すると標準入力を読む。ディレクトリの一括探索は
行わない。人が読む原稿を指定し、内部メモまで検査対象に広げない。

通常の Markdown のコードフェンスとインラインコードは除外する。
`--include-code` または `--input-format text` で、その部分も検査できる。
Markdown の完全な構文解析は行わないため、引用やリストの中の複雑な
コードブロック、HTML、リンク先、正式名称などは文脈を読んで判断する。
コード内でも利用者に表示するメッセージは、文字列を取り出して検査する。

## 結果の扱い

位置は行・列ともに 1 始まりで、列は Unicode の文字数で数える。
JSON の `findings` には位置、該当箇所、行全体、見直す理由、言い換えの候補、
残す場面を含める。候補がない場合は空の配列になる。

通常の終了コードは候補の有無によらず `0`。`--fail-on-findings` を付けると
候補がある場合に `1` を返す。入力の読み込みに失敗した場合などは `2`。
`1` は「原稿を見直す」という意味で、単語の使用が誤りだと断定するものではない。
適切な用語が残る原稿に、この終了コードをそのまま投稿の必須条件として使わない。

「版」は番号や「この版」などの表現を中心に拾う。ソフトウェアか書籍かは
判断しない。「出版」「版画」「日本語版」などは通常の検出対象から外れる。
ほかの語でも、専門用語や自然な日常表現を候補として拾う場合がある。
検出されなかった表現や、文章全体の自然さも別途確認する。

## 候補を追加する場合

`word-choice.json` の `rules` に、安定した `id`、語、正規表現、理由、
言い換えの候補、残す場面、文脈つきの例を追加する。正規表現は Python の
`re` で扱い、空文字列には一致させない。検出例と不要な検出を避ける例を
`tests/test_natural_japanese_scripts.py` に追加する。

読みやすさ全般を検査する既存の
[textlint の AI writing プリセット](https://github.com/textlint-ja/textlint-rule-preset-ai-writing)
がある場合は併用する。このスクリプトは語の見直し候補を補うもので、
そのプリセットと同じ検査は行わない。
